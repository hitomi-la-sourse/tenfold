# セキュリティ方針

## サーバー主導

クライアントから送るのは希望操作だけです。手札、カードランク、手番、効果結果、勝敗は信用しません。操作は必ずサーバーの完全状態に照らして検証します。

## 情報秘匿

通常のプレイヤービューへ以下を含めません。

- 山札の内容と順序
- 転生札の内容
- 生存中の他プレイヤーの手札
- 死神のA・Bの内容（手番プレイヤー）
- 他プレイヤーの占師結果
- CPU内部の知識

公開処刑の解決中だけは仕様どおり2枚を公開します。脱落・決着時は公開対象の手札だけを明示的に含めます。

## 入力と通信

- 受信payloadをZodで検証
- ニックネームは1〜16文字、制御文字を除去
- 手番外、他人としての操作、存在しないカード・対象、二重送信を拒否
- Socketごとのイベント頻度制限
- HTTPレート制限、helmet、CORS許可元制限
- Socket payload上限

## トークンとログ

再接続トークンは暗号学的乱数32byteをbase64url化します。URL、公開ログへ載せません。pinoのredact設定でトークン、手札、山札を除外します。内部スタックトレースをクライアントへ返しません。

## ライフサイクル

未開始の放置ルームは60分、終了ルームは30分以内に削除します。切断席は60秒保持し、その後CPUへ不可逆に交代します。

## 運用確認

- HTTPS/WSSを強制
- `WEB_ORIGIN` を正確な本番Webオリジンへ限定
- ゲームサーバーをスリープさせない、または無料枠のスリープ挙動を利用者へ案内
- リバースプロキシのWebSocketタイムアウトを対戦時間より長くする
- 依存更新時にlint、typecheck、test、build、E2Eを実行
